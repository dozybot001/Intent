# Intent 7.1.0

Released 2026-10-30. Readable CLI, structured checkpoints, Claude Code hooks, a redesigned IntHub and a hardened server. The `.intent/` format and the JSON contract are unchanged.

## CLI

- In a terminal, `itt` prints readable text: `itt inspect` shows each open goal with Next, Blocker, Boundary and Verified; errors go to stderr as `error:` and `hint:`. Agents and scripts keep getting JSON: whenever stdout is not a terminal, an agent host is detected, or `--json` / `ITT_FORMAT=json` is given.
- New `itt log [--intent ID] [-n N | --all]` and `itt show ID`, modelled on `git log` and `git show`.
- `itt snap create` takes `--verified`, `--boundary`, `--next`, `--blocker` and `--constraints`, stored as a write-once `checkpoint` on the Snap. Snaps without them keep the exact previous shape.
- `itt --version`, help text for every command, empty WHAT rejected, numeric ordering past 999 objects, and unexpected failures reported as `INTERNAL_ERROR` instead of a traceback (`ITT_DEBUG=1` re-raises).
- `itt status` stays local until a remote is configured.

## Agent hosts

- Claude Code: `itt init --host claude-code` (or `itt maintenance on --host claude-code`) adds Intent's UserPromptSubmit and Stop hooks to `.claude/settings.local.json` and leaves other settings alone. The repository is also a Claude Code plugin marketplace for the Skill.
- Codex stays the default and is unchanged.

## IntHub

- Redesigned as one continuity workspace: a continuation brief with each open goal's next step and blocker, a detail sheet with history, Cmd/Ctrl+K search, a copyable brief for the next agent, and a first-run setup guide. Status colour is always paired with text or an icon.
- Deleting your Tenon account removes your IntHub data.
- Hardening: IntHub Local accepts only same-origin JSON requests on loopback; routes are matched before bodies are read; host-only `__Host-` session cookie; sign-in rate limiting; socket timeouts and a larger listen backlog; graceful drain on shutdown; no unauthenticated history on non-loopback interfaces.
- Web fixes from an independent review: search with IME and typed text, sheet focus and history, mobile layout, and sign-out clearing private content.

## Packaging

- The distribution is now **`intent-history`**, because `intent-cli` and `itt` on PyPI belong to unrelated projects. The command stays `itt`.
- The installers use uv or pipx when present and otherwise a private virtual environment, so they work on externally managed Pythons (Homebrew, Debian). They remove an earlier `intent-cli` install of Intent, and the PowerShell installer no longer closes the window on errors.
- Classified as Beta. GitHub Actions runs the test suite only (Python 3.9, 3.13 and 3.14 with PostgreSQL).

## Upgrading

- Re-run the installer:

  ```bash
  curl -fsSL https://raw.githubusercontent.com/dozybot001/Intent/main/scripts/install.sh | bash
  ```

  With pipx directly: `pipx uninstall intent-cli`, then `pipx install "intent-history @ git+https://github.com/dozybot001/Intent.git@v7.1.0"`. Check that `itt --version` prints 7.1.0.
- The IntHub session cookie was renamed, so each browser had to sign in again once.
- `--token` and `INTHUB_TOKEN` are sent only to the command's `--api-base-url`, your saved endpoint or loopback, never to an endpoint named only in a project's `.intent/hub.json`. Remote IntHub URLs must use HTTPS. If a project points at another endpoint, run `itt auth login --api-base-url URL` for it.
- A script that runs `itt` attached to a terminal and parses its output should pass `--json`.
