# Intent 7.5.0

Released 2026-10-30. IntHub gets teams and public projects: work on a project together with roles, publish one for anyone to read, and see all your projects in one place.

## Teams

- **Teams and roles.** Create a team and add people with an invite link (single use, valid for 7 days). Admins manage members and settings, members read and push, and viewers read.
- **Team projects.** `itt remote add origin URL --project TEAM/NAME` creates and pushes a team's project. A name without a prefix is still a personal project, so existing clones are unaffected.
- **Transfer.** Move a project to a team you administer, or back to your account. Clones follow, like a rename.
- A team always keeps an admin. If an admin's account is deleted, the longest-standing member takes over; a team with nobody left is deleted with its projects.

## Public projects

- **Private or public.** New projects are private, and a push never changes that. Going public takes the project name typed in Settings.
- **Read-only pages.** Anyone with the link can read a public project without signing in: overview, Intents, Flow, Timeline, History, Decisions and search. Members and settings stay hidden.
- **Author emails stay hidden.** They come from Git config and can be private, so visitors and non-members see names only. `itt pull` and export stay members-only, because they carry the complete snapshot.

## IntHub

- **Home.** With two or more projects, `/` lists yours and your teams', most recently synced first, with how many active Intents are blocked.
- **Header.** The gear is now Settings (appearance, language, refresh, about), and the account menu holds account things only: profile, access tokens, teams, the Tenon account center and sign out.
- **Settings layout.** Account, team and project settings share one layout, with navigation on the left and one section at a time. The account page moved from `/settings` to `/account`.
- **Before the first push.** A project's manager can reach its Settings as soon as it exists, so an empty project can be renamed, published or deleted.
- **Dead links.** A project link that opens nothing now says so instead of quietly showing something else.

## CLI

- `--project` accepts `TEAM/NAME`.
- `PERMISSION_DENIED` and `TEAM_NOT_FOUND` reach Agents with their own codes instead of `SERVER_ERROR`.
- itt 7.4 and earlier cannot use team projects, and report `INVALID_REMOTE_SNAPSHOT` for a project moved to a team until upgraded.

## Upgrading

Re-run the installer, or `pipx install --force "intent-history @ git+https://github.com/dozybot001/Intent.git@v7.5.0"`. Nothing in `.intent/` changes.

The IntHub database moves to schema v7, which only adds tables and columns. Every existing project stays private and personal. After a rollback the previous image ignores the new data: team projects and public pages become unreachable until you upgrade again.

## Verification

- 576 tests pass locally on Python 3.14 with PostgreSQL 16. CI runs them on Python 3.9, 3.13 and 3.14.
- The PostgreSQL tests cover teams, visibility and transfer, including two admins demoting each other at the same moment.
- The web tests cover the new pages with a stubbed API. End-to-end flows ran in headless Chrome against hosted-mode and local hubs with only the sign-in stubbed: invites, roles, visibility, transfer and visitors. The real CLI pushed team projects and followed a transfer and a team URL change.
- The layout audit ran 624 page states at 1440, 1024, 768, 721, 390 and 320 px in light and dark, English and Chinese, and found no problems.
