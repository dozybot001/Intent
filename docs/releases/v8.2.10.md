# Intent CLI 8.2.10

Released 2026-11-20.

- **Changed: `itt --version` names the publisher.** It prints the version, then `Publisher: Tenon AI (https://tenonai.cn/)`. `itt version` prints the same, and its JSON adds `publisher` and `website` next to `version`.
- **Changed: the README says what `itt` collects.** It collects no telemetry or usage data. IntHub is introduced by its one-line definition, a cloud platform for Intent hosting and collaborative development, and you don't need it to use `itt`.
- **Added: IntHub error pages.** When IntHub fails on its side, browsers get a 500 page in English and Chinese with a link home, and API callers still get the JSON error. While the app is down or restarting, browsers see a maintenance page and the CLI gets a JSON `SERVICE_UNAVAILABLE` with `Retry-After`.
- **Fixed: the loading placeholder is announced properly.** Screen readers now read it as a status message; before, its label was attached to an element that may not carry one.
- **Security: every release checks dependencies for known vulnerabilities.** The release gate runs pip-audit and stops on any finding. The first run found one in the test runner, so pytest goes from 8.4.2 to 9.0.3 (Python 3.9 keeps 8.4.2, which only runs in CI). Nothing that runs in production changed.

Run `pipx upgrade intent-history`, or re-run the installer.

## 中文

2026-11-20 发布。

- **变更：`itt --version` 写明出品方。** 先输出版本号，再输出 `Publisher: Tenon AI (https://tenonai.cn/)`。`itt version` 输出相同内容，它的 JSON 在 `version` 旁增加 `publisher` 和 `website`。
- **变更：README 写明 `itt` 收集哪些数据。** 不收集任何遥测或使用数据。介绍 IntHub 时改用它的一句话定义「云端 Intent 托管与协作开发平台」，并说明不用它也能使用 `itt`。
- **新增：IntHub 错误页。** IntHub 自身出错时，浏览器看到中英文的 500 页面和返回首页的入口，接口调用方仍然收到 JSON 错误。应用停机或重启期间，浏览器看到维护页，命令行收到带 `Retry-After` 的 JSON `SERVICE_UNAVAILABLE`。
- **修复：加载占位能被正确朗读。** 读屏软件现在把它当作状态消息读出；之前它的标签加在了不该带标签的元素上。
- **安全：每次发布都检查依赖的已知漏洞。** 发布门禁会运行 pip-audit，发现问题就停止发布。第一次运行在测试工具里发现一个漏洞，所以 pytest 从 8.4.2 升到 9.0.3（Python 3.9 仍用 8.4.2，它只在 CI 中运行）。生产环境里运行的部分没有变化。

运行 `pipx upgrade intent-history`，或重新运行安装脚本。
