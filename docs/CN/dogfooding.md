# 当前版本自用验证协议

中文 | [English](../EN/dogfooding.md)

这套协议用于验证当前 Intent CLI 与 Skill 能否以低打扰方式提供关键接续信息。历史演示，以及后来从代码重新发现的事实，都不能算成当前版本的恢复证据。

## 案例设置

连续使用接下来自然发生的开发接续，不制造 benchmark 任务。

1. 在自然停点，明确要求当前 agent 用 Intent 记录。
2. 新开 session 或换一个看不到旧聊天的 agent。
3. 在读取代码、测试或其他笔记前，只允许先运行 `itt inspect`。如果目标显示 `has_more: true` 且最新检查点仍不足，再允许 `itt inspect --intent ID --history 3`。
4. 第一次修改代码前，陈述目标与原因、当前工作边界、下一步或 blocker，以及现行 Decision。
5. 给每项恢复信息标注来源。

| 标记 | 含义 |
|---|---|
| `I` | Intent 输出直接提供 |
| `R` | 后来从代码、测试或其他材料重新发现 |
| `U` | 用户重新解释 |
| `×` | 遗漏或理解错误 |

## 通过标准

低打扰要求：额外用户轮次不超过 1，用户注意力不超过 3 分钟，没有修复操作和明显垃圾记录。

有效接续要求：目标、工作边界和约束均来自 `I`；用户不需要重讲旧事实；第一次实质动作方向正确。出现严重错误动作则直接失败。

- 前 5 次自然接续至少 4 次同时通过两项标准，才称为**初步可用**。
- 10 次中至少 8 次通过且没有严重错误，才形成**可信的自用证据**。

## 案例记录表

每次接续一行。不能在事后把 `R` 或 `U` 改算成 `I`。

| 案例 | 目标 | 边界 | 下一步 / blocker | Decision | 首次动作 | 额外轮次 | 注意力 | 结果 |
