# IntHub 管理与协作

状态：7.3 的设置与管理、7.4 的身份与历史、7.5 的团队和公开已实现；设备码登录待确认。

IntHub 对标 GitHub。现在推送、浏览、接续这条主线已经通了，缺的是三层：管理（设置、改名、删除、导出）、历史（每次推送改了什么）、协作（团队、可见性、公开页）。本文给出这三层的模型和分期。

## 原则

- **浏览器管项目，CLI 写历史。** 改名、删除、可见性、成员这类管理操作在网页上完成；语义历史仍然只接受 CLI 的访问令牌推送，网页会话永远不能改写历史。这是现有的安全边界，不变。
- **默认私有。** 新项目一律私有；改成公开必须在设置里明确确认，推送永远不会顺带公开项目。
- **能删、能带走。** 用户可以随时删除单个项目，或把数据导出带走。数据推上来就删不掉，开发者不会放心用。
- **照 GitHub 的习惯来。** 用户已经熟悉 GitHub，名称、层级和操作位置尽量一致，不另起概念。

## GitHub 的可见性怎么分

GitHub 的仓库可见性只有**公开**和**私有**两档。第三档 **internal**（企业内所有成员可见）只在 GitHub Enterprise 的组织里有。

「团队内可见」在 GitHub 里不是一档可见性，而是归属加授权：仓库归组织所有并设为私有，再给组织成员一个基础权限（例如全员只读），或者只授权给组织里的某几个团队。权限分为 Read、Triage、Write、Maintain、Admin 五级。

## IntHub 的模型

把 GitHub 的「组织」简化成**团队**：一个团队就是一组成员，不再往下分子团队。

| | 谁能看 | 谁能推送 | 谁能管理 |
|---|---|---|---|
| 个人私有项目 | 本人 | 本人 | 本人 |
| 团队私有项目 | 团队全体成员 | 管理员和成员 | 管理员 |
| 公开项目 | 所有人，包括未登录的访客 | 同上（个人或团队） | 同上 |

- **可见性只有私有和公开两档**，和 GitHub 一样。团队私有项目自然只对团队可见，这样就有了「私有、团队内、公开」三层效果，但用户只需要理解一个开关。
- **所有者是个人或团队。** 项目名在所有者下唯一。团队项目的完整名是 `团队/项目`，与 GitHub 的 `owner/repo` 一致；个人项目不带前缀，因为 Tenon 账号没有用户自选的用户名。项目可以在个人和团队之间转移。
- **团队内三种角色：** 管理员（成员、设置、删除）、成员（阅读和推送）、只读成员（只能阅读）。GitHub 的五级对小团队太细，三级够用。
- **公开项目只读。** 访客可以看概览、意图、流转、时间线、历史、决策和搜索，看不到成员和设置；推送仍然需要成员身份。
- **公开项目对访客隐藏作者邮箱。** 作者邮箱来自 git 配置，可能是私人邮箱，所以访客和非成员只看到作者姓名。`itt pull` 和导出只对成员开放：它们带完整快照，去掉邮箱就会改变修订的校验和。
- **链接用项目 ID。** 公开链接是 `/?project=ID`，项目改名或转移后仍然有效。

## 设置

顶栏分两层：

- **设置**（齿轮）：外观、语言、刷新项目数据、关于。不需要登录，访客也能用。
- **账号**（头像）：只放账号相关的入口：个人资料、访问令牌、团队、Tenon 账号中心、退出登录。

账号、团队和项目设置用同一种版式：左侧导航，右侧一次显示一个分区。

**账号页**（`/account`）：

- 个人资料：名称和登录方式来自 Tenon，这里只读展示，并链接到 Tenon 修改；关联 Snap 的邮箱说明；删除账号（沿用现有的 Tenon 流程）。
- 访问令牌：创建时填名称、选有效期（30、90、365 天）；列表显示创建时间、最后使用时间、到期时间和状态；可以随时作废。新令牌只在创建后显示一次，显示在列表里，不再弹窗。
- 团队：我所在的团队和角色，创建团队。

**团队页**（`/teams/团队`）：

- 成员：角色调整、移除、邀请链接、退出团队。团队至少保留一名管理员。
- 项目：团队的全部项目。
- 设置（管理员）：名称和地址；删除团队，需要输入团队地址确认，团队的项目一起删除。

**项目设置**（项目页的「设置」标签，只有管理者看得到）：

- 常规：改名；可见性（改为公开要输入项目名确认）；导出 JSON，内容为当前语义快照和修订列表，`itt pull` 能恢复的内容都在里面。
- 成员：团队项目显示团队成员和角色。
- 危险操作：转移（到你管理的团队，或回到个人）；删除项目，需要输入项目名确认。

## 改名和转移后 CLI 怎么办

- 新版 CLI 推拉时带上项目 ID，IntHub 按 ID 找项目并返回当前名称，CLI 自动更新本地配置并提示一句。转移项目、修改团队地址也走这条路。
- 旧版 CLI（7.2.1 及以前）按名称查找，改名后会得到 `REMOTE_CHANGED`，不会误建一个同名新项目；升级 itt 后恢复正常。不要用 `itt remote add` 改名：它会清掉同步基线，本地有未推送内容时会变成「已分叉」。
- 不保留旧名跳转。GitHub 会把旧仓库地址重定向到新地址，但 IntHub 的项目名只给 CLI 用，没有对外链接需要兼容。

## 身份（第二期，先于团队）

做法照 Git：作者身份由本人声明，平台负责关联到账号并验证。

- **每个对象记录作者。** 新建的 Intent、Snap、Decision 写入 `author: {name, email}`。取值顺序和 Git 一样：先看环境变量 `ITT_AUTHOR_NAME`、`ITT_AUTHOR_EMAIL`，再看 git 的 `user.name`、`user.email`（先项目、后全局）。大多数开发者已经配好 git，不需要额外设置。
- **没有身份时照常记录。** Agent 的记录不能因此中断，但 `itt init`、`itt status`、`itt doctor` 会提示设置。旧对象没有作者，界面上就不显示。
- **Agent 单独记录。** 现有的 `origin` 字段记录是哪个 Agent 写的（claude-code、codex），作用相当于 Git 的 `Co-authored-by`。界面显示为「曾德扬 · Claude Code」。
- **每次推送记录推送人。** 修订表新增两项：令牌认证的推送账号，以及 CLI 声明的推送人姓名和邮箱。IntHub Local 没有账号，只有声明的身份。
- **修改归到修订。** 状态变化、关系变化不单独记作者，而是归到带来这次变化的那条修订，就像 Git 用 commit 标记每一处修改。
- **IntHub 关联身份。** 登录时保存 Tenon 已验证的邮箱（目前只取了名称）。作者邮箱与某个成员的已验证邮箱一致时，显示这个成员的头像和名称。对不上的，照记录显示原始名称，和 GitHub 上未关联账号的 commit 作者一样。
- **已验证标记。** 如果一条内容还是由作者本人的账号推送的，再标「已验证」，类似 GitHub 的 Verified。推送时服务端算出这次新增了哪些对象，并和修订一起保存，所以显示时不用重算。
- **设置页说明关联条件。** 页面告诉用户：git 的 `user.email` 要设成哪个邮箱，Snap 才会关联到这个账号。
- **不做签名。** Git 要靠 GPG 或 SSH 签名来证明作者身份；IntHub 的推送本来就要令牌认证，「推送账号就是作者」足以作为验证依据。

## 历史（第二期）

- **历史页：** 每次推送是一条修订，显示时间、推送人和变化摘要，例如「新增 2 个意图、5 个 Snap，废弃 1 条决策」，并可按作者筛选，相当于 `git log --author`。
- **语义 diff：** 对比相邻两个修订的快照，按对象列出新增、状态变化和关系变化，相当于 GitHub 的 commit 详情页。
- **Snap 关联 git：** CLI 记录 Snap 时，如果项目在 git 仓库里，附带当前 commit。项目有 GitHub 远端时，IntHub 把它链接到对应的 commit 页面。

## 团队与协作（第三期）

- 创建团队、用邀请链接加人（一次性，7 天有效，服务端只存哈希）、调整角色、移除成员。接受邀请是浏览器操作，访问令牌不能加入团队。
- 团队项目的 CLI 写法：`itt remote add origin URL --project 团队/项目`。不带前缀的仍是个人项目，现有配置不受影响。成员和管理员可以新建和推送，只读成员可以拉取。
- 账号被删除时，它管理的团队不会失去管理员：由加入最早的成员接任，优先普通成员；没有其他成员的团队连同项目一起删除。
- **并发推送仍是快进。** 多人往同一个项目推送时，后推的人要先 `itt pull`。Agent 可以自动做这一步，但两边都改过就只能人工处理。真正的语义合并属于 Intent 8（见[语义版 Git](semantic-git.md)），团队协作会是它的主要用户。
- **跨项目首页：** 列出我和我所在团队的项目，按最近同步排序，并标出多少活跃意图受阻。只有一个项目时直接打开它。

## CLI 登录（待确认）

现在 `itt auth login` 要先在网页上创建令牌，再复制粘贴到终端。建议改成和 `gh auth login` 一样的设备码登录：

1. 终端显示一个一次性代码，并打开 IntHub 的授权页。
2. 用户登录后核对代码，点「授权」。
3. CLI 自动拿到令牌，令牌按「itt · 机器名」命名，可以在设置里作废。

这样令牌不会出现在屏幕上，SSH、容器和 Agent 环境里也能用。粘贴令牌的方式保留，作为没有浏览器时的备选。
