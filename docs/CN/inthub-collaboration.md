# IntHub 协作指南

中文 | [English](../EN/inthub-collaboration.md)

IntHub 是可选的服务，用来浏览和共享 Intent 历史。本文介绍托管版 [inthub.tenon.asia](https://inthub.tenon.asia)。它的模型沿用 GitHub：每个项目有一个所有者，可以私有或公开，团队给成员分配角色。

有两条规则贯穿始终：

- **浏览器管项目，CLI 写历史。** 改名、可见性、团队和删除都在浏览器里完成。历史只能通过 `itt push` 加访问令牌改变。浏览器会话不能写历史，令牌也不能做任何管理操作。
- **默认私有。** 新项目一律私有。公开项目必须明确确认，推送不会改变可见性。

本地 hub（`itt hub start`）运行在你自己的机器上，没有账号、团队、可见性和配额，但仍然可以改名、导出和删除项目。

| 位置 | 内容 |
|---|---|
| **设置**（齿轮图标） | 访问令牌、团队、用量 |
| **账号**（头像） | 个人资料、危险操作 |
| 团队页 `/teams/团队` | 成员、项目、设置（仅管理员） |
| 项目的**设置**标签（仅管理员） | 常规、成员（团队项目）、危险操作 |

## 账号与登录

IntHub 账号就是 Tenon 账号。在浏览器里可以用 GitHub、Apple 或邮箱登录。IntHub 不申请访问你的代码仓库，浏览器会话最长保持 30 天。名称和邮箱来自 Tenon，**账号**里只做展示，并提供修改入口的链接。

在终端登录时运行 `itt auth login`：

1. 终端显示一个 8 位字母代码；如果这台机器有浏览器，会同时打开 `/device` 页面。
2. 在任意浏览器里登录，输入代码，核对设备名称，然后点**授权**。
3. CLI 收到一个 90 天有效的访问令牌，名称为「itt on 机器名」。

代码 10 分钟后过期。代码始终要手动输入，所以别人没法发一个链接让你批准。第 2 步可以在另一台设备上完成，所以 SSH 和容器里也能用。`itt auth status` 可以查看登录状态。

每个 Intent、Snap 和 Decision 都会记录作者，取自 Git 配置，或 `ITT_AUTHOR_NAME` 和 `ITT_AUTHOR_EMAIL`。如果你的账号推送的对象，作者邮箱正是你的 Tenon 邮箱，IntHub 会标记为**已验证**。**账号**里有把 Git 设成这个邮箱的命令。

## 项目与可见性

项目的所有者是你的账号或一个团队。项目名在所有者下唯一。个人项目写作 `项目`，团队项目写作 `团队/项目`，其中「团队」是团队 URL。首页列出你和你所在团队的项目，最近同步的排在前面。

项目通过 CLI 创建：

```bash
itt push    # 个人项目，以当前目录命名

itt remote add origin https://inthub.tenon.asia --project acme/checkout    # 团队项目
itt push
```

项目只有私有和公开两种，没有第三种设置。团队的私有项目就是中间一层：团队全体成员可读，其他人不可读。

| 项目 | 在浏览器里阅读 | `itt pull` | `itt push` | 管理 |
|---|---|---|---|---|
| 个人私有 | 本人 | 本人 | 本人 | 本人 |
| 个人公开 | 所有人 | 本人 | 本人 | 本人 |
| 团队私有 | 团队全体成员 | 团队全体成员 | 管理员和成员 | 管理员 |
| 团队公开 | 所有人 | 团队全体成员 | 管理员和成员 | 管理员 |

管理指改名、修改可见性、转移、在设置里导出和删除。

要公开项目，打开项目的**设置**标签，选择**设为公开**，再输入项目名。IntHub 会先检查当前历史里有没有疑似凭据：私钥、API 密钥、访问令牌和 URL 里的密码。如果发现，会列出相关对象。检查之后，如果仍想公开，再确认一次。**设为私有**立即生效，但已经读过项目的人可能留有副本。

项目链接是 `/?project=ID`，改名或转移后仍然有效。IntHub 没有公开目录，访客要通过链接才能打开公开项目。

管理员在项目的**设置**标签里改名，在**危险操作**里把项目转移到自己管理的团队，或转回自己的账号。转移要输入项目名。新所有者必须有空余的项目名额，并且没有同名项目。转移之后，谁能阅读、推送和管理都跟随新所有者。

克隆会在下一次推送或拉取时跟上改名、转移或新的团队 URL，因为它们按项目 ID 查找项目。很旧的 `itt` 会报告 `REMOTE_CHANGED`，升级后恢复正常。不要用 `itt remote add` 跟进改名：它会丢掉项目 ID，这份副本就不再跟随项目。

## 团队与角色

团队是一组共同拥有项目的账号，不再往下分子团队。在**设置 → 团队**里填写名称和 URL 即可创建。URL 只能用小写字母、数字和连字符，最长 39 个字符，首尾不能是连字符。创建者成为管理员。一个账号最多创建 10 个团队。

| 角色 | 阅读和拉取 | 推送和创建项目 | 管理成员、团队及其项目 |
|---|---|---|---|
| 管理员 | 可以 | 可以 | 可以 |
| 成员 | 可以 | 可以 | 不可以 |
| 只读成员 | 可以 | 不可以 | 不可以 |

- 只有团队成员能打开团队页。团队里的人都能看到成员列表，只有管理员能看到邮箱。
- 管理员可以调整角色、移除成员、修改团队名称和 URL。
- 任何人都可以退出团队。团队至少保留一名管理员，所以最后一名管理员要先把别人设为管理员。
- 团队变更都是浏览器操作。访问令牌只能使用成员身份，不能改动它。

## 邀请

管理员在团队页用邀请链接加人：

- 选择角色，创建链接。链接只显示一次，IntHub 只保存它的哈希。
- 链接只能用一次，7 天后过期。
- 待接受的邀请会列出来，可以作废。一个团队最多同时有 50 个。
- 邀请不绑定邮箱，任何人打开链接并登录后都能以该角色加入，所以只发给你想邀请的人。
- 接受邀请要在浏览器里完成，访问令牌不能加入团队。

## 访客能看到什么

访客指不属于项目、却在阅读公开项目的人：未登录，或者登录了非成员账号。

访客可以阅读概览、意图、流转、时间线、历史和决策标签，也可以搜索项目。他们能看到作者和推送人的姓名。

访客不能：

- 看到作者或推送人的邮箱。邮箱来自 Git 配置，可能是私人邮箱。
- 看到设置标签或成员列表。
- 运行 `itt pull`、`itt clone` 或导出。它们都带有作者邮箱，去掉邮箱就会改变修订摘要。
- 推送。

对项目之外的人来说，私有项目和不存在的项目看起来没有区别。

公开项目会向所有不能管理它的人显示**举报此项目**。被 IntHub 下架的项目会变成私有，要联系支持才能重新公开。

## 推送与拉取权限

上面的表格列出了谁能做什么。拉取需要成员身份，公开项目也一样。推送需要管理员或成员角色，或者是个人项目的所有者。两者都使用访问令牌。

每个项目只有一份共享历史，推送只做快进：

- 如果别人先推送了，运行 `itt pull`，再 `itt push`。
- 如果双方都记录了内容，`itt status` 会报告 `diverged`。运行 `itt pull` 合并远端，处理冲突后再 `itt push`。

合并的工作方式见[语义版 Git](semantic-git.md)。

## 访问令牌

CLI 用访问令牌读取和推送。令牌属于你的账号，拥有账号的全部权限，不能限定到单个项目。

- `itt auth login` 会创建令牌并替你保存。
- 在**设置 → 访问令牌**里可以手动生成，填写名称，选择 30、90 或 365 天有效期。令牌只在列表里显示一次。每台机器或每个 Agent 各生成一个。
- 列表显示有效的令牌及其创建时间、最后使用时间和到期时间。**作废**后令牌立即失效。
- 无人值守的机器可以设置 `INTHUB_TOKEN` 或传 `--token`。
- `itt auth logout` 只从这台机器上移除令牌。令牌在到期或作废之前一直有效。
- 令牌不能管理项目、团队、其他令牌或账号。这些操作需要浏览器会话。

## 配额

每个所有者（账号或团队）在托管版上可以保存 100 个项目和 1 GB 历史。**设置 → 用量**显示你个人的额度和每个团队的额度。

每次推送都保存一份完整快照，所以存储随推送增长。达到上限后，创建项目或推送会失败，并返回 `QUOTA_EXCEEDED`。删除项目会释放它占用的存储。

## 导出与删除

**导出项目。** 在项目的**设置**标签里，用**下载导出文件**保存一个 JSON 文件，内容是当前快照和修订列表。要把完整历史带到另一台机器，用 `itt clone`。

**删除项目。** 在项目**设置**标签的**危险操作**里输入项目名。这会从 IntHub 删除项目及其历史，无法撤销。本地的 `.intent/` 不受影响。要重新发布，运行 `itt hub link`，再 `itt push`。

**删除团队。** 在团队的**设置**页输入团队 URL。这会从 IntHub 删除团队及其全部项目，无法撤销。本地的 `.intent/` 目录不受影响。

**删除账号。** 在**账号 → 危险操作**里发起，到 Tenon 账号中心确认。这会从 IntHub 删除你的账号、个人项目和访问令牌。你是唯一管理员的团队，交给加入最早的成员；没有成员时，交给加入最早的只读成员。团队里没有其他人时，团队连同项目一起删除。本地的 `.intent/` 不受影响。
