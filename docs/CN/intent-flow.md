# 意图流转：Intent 之间的关系

中文 | [English](../EN/intent-flow.md)

状态：已在 Intent 7.2 实现。

## 原则

- 流转只发生在 Intent 之间。Snap 必须挂在一个 Intent 下，这本身就是操作与语义之间的归属关系，因此不再给 Snap 加别的关系。
- 关系只回答两个问题：这个目标从哪里来；它受什么制约。不属于这两类的情况一律视为无关，不记录。
- 关系的状态不单独存储，而是由两端 Intent 的状态推算出来，所以不会与对象状态不一致，合并时也不会产生冲突。
- 和其他对象一样只追加：关系可以新增、可以撤回，但已写入的记录不修改、不删除。
- 不依赖语义版 Git，可以先于 8.0 发布；迁移到格式 2 时原样保留。

## 五种关系

| 类型 | 写法（B 相对 A） | 含义 | 流转图 |
|---|---|---|---|
| **组成** `part_of` | `--part-of A` | B 是 A 的一部分：A 要完成，B 必须先完成或放弃 | 从 A 分出，结束后汇回 A |
| **衍生** `derived_from` | `--derived-from A` | B 是做 A 时产生的新目标，但 A 的完成不依赖 B | 从 A 分出，不汇回 |
| **继承** `succeeds` | `--succeeds A` | B 接过 A 的目的继续推进：下一阶段、改换方案、合并重复目标 | A 的泳道流入 B |
| **依赖** `depends_on` | `--depends-on A` | B 要等 A 完成才能推进 | 从 A 指向 B 的细箭头 |
| **对立** `conflicts_with` | `--conflicts-with A` | A 与 B 不能都按现在的表述达成：互斥的方案，或相反的目标 | 双向虚线 |

为什么是这五种：前三种回答「从哪里来」，分别是在 A 之内（组成）、因 A 而生但在 A 之外（衍生）、接替 A（继承）；后两种回答「受什么制约」，分别是必须等 A（依赖）、不能与 A 并存（对立）。用它们就能画出分支、流转与汇合：

- **分支：** 组成、衍生，以及一个目标被多个后继继承（分流）。
- **流转：** 继承。
- **汇合：** 子目标结束后汇回上级；多个目标被同一个后继继承，比如合并重复目标，或几个目标合成一个。

「继承」指接续目的，类似接班，不是面向对象里的子类。更具体的子目标属于组成或衍生。

有意不提供「相关」「参见」这类弱关系：它们没有判断标准，Agent 会滥用，图很快就会变成噪音。

## 关系状态

| 类型 | 状态（由两端状态推算） |
|---|---|
| 组成 | 进行中 → 已完成 / 已放弃；若 A 已结束而 B 仍在进行，给出提示 |
| 衍生 | 无，只表示来源 |
| 继承 | 待交接（A 仍在进行或暂停）→ 已交接（A 已结束） |
| 依赖 | 阻塞中（A 未完成）→ 已满足（A 已完成）/ 已失效（A 被取消，需要处理） |
| 对立 | 未解决（双方都未结束）→ 已解决（至少一方已结束） |

需要处理的状态（阻塞中、已失效、未解决的对立、待交接）会出现在 `itt inspect`、开局上下文和 IntHub 的接续简报里。

## 规则

- 同一对 Intent 之间同时最多一条有效关系。
- 每个 Intent 最多有一个上级：组成与衍生只能二选一，并且只能指向一个目标。
- 上级关系（组成与衍生）、继承、依赖都不能成环；不能关联自己；关联的目标必须存在。
- 已结束的 Intent 不能再新增组成部分。

## 命令

```bash
itt intent create "接入 Apple Pay" --why "…" --part-of intent-003
itt intent relate intent-007 --depends-on intent-004        # 任何时候补记
itt intent unrelate intent-007 intent-004                    # 撤回这对 Intent 之间的有效关系
itt intent cancel intent-005 --into intent-008 --reason "重复"  # 结束，并由 intent-008 继承
itt decision create "支付只走 PaymentIntent" --why "…" --from intent-003
```

`done` 和 `cancel` 的 `--into` 等于结束这个 Intent，并在目标 Intent 上记录一条继承关系。如果两者原本对立，这条对立关系会被撤回：为了一方而结束另一方，本身就解决了对立。`itt show ID` 列出两个方向的关系及其状态。

## 存储

Intent 新增可选字段 `relations`，写在声明关系的一方（B）：

```json
"relations": [
  {"type": "part_of", "intent": "intent-003", "created_at": "2026-11-02T08:15:00+00:00"},
  {"type": "depends_on", "intent": "intent-004", "created_at": "…", "removed_at": "…"}
]
```

撤回只追加 `removed_at`。没有关系的 Intent 不写这个字段，所以现有对象和校验和都不变。

## Decision 的来源

目前 Decision 是全局生效的：创建时自动关联当时所有进行中的 Intent，之后新建或恢复的 Intent 也会自动关联，但并不记录它是从哪个 Intent 产出的。

新增可选字段 `source_intent_id`，用 `--from ID` 在创建时写入，之后不变。不写就是无源，表示项目级决策。全局生效的方式不变。

不做自动推断：在某个目标进行期间写下的项目级规则，不一定出自这个目标，记错比不记更误导。Skill 会提示 Agent：决策确实出自当前目标时，加上 `--from`。

## 流转图

IntHub 新增「流转」页：

- 有关系的 Intent 分组摆放：有未结束工作的组在前，先向右、再向下填满页面。每个 Intent 是一张卡片，右下角显示创建时间。
- 组成和衍生的子目标排在上级右侧一列，共用一条主干；继承者接在同一行；依赖或对立的 Intent 排在对方右侧。
- 已结束的组成部分汇到上级所在行的一个点上。只有一条线汇入、后面也没有继承者时，不画汇合点。
- 线型按上表区分；节点颜色只表示状态，并始终配有文字。
- Decision 画成菱形，挂在来源 Intent 上；无源的 Decision 放在顶部的「项目」一栏；已废弃的显示为空心。
- Snap 不画成节点，只在节点上显示数量；点击节点打开现有的详情侧板。
- 可以隐藏已结束的目标，或只看某个目标周围的关系。

验收：五种关系各做一份测试历史，再用真实项目渲染。只看图、不打开 Snap，就能说清目标如何分出、接续和汇合，才算完成。

## 兼容性

- 旧版 `itt` 读到新字段会直接忽略。但如果某个已存在的 Intent 后来新增了关系，7.1 及更早的版本 pull 时会被快进检查拒绝，需要升级到 7.2。Snap 和其他已写入的字段保持原有的严格程度。
- 8.0 迁移原样保留这些字段。语义合并时，关系记录取并集，撤回优先；如果合并后某个 Intent 出现两个上级或形成环，就作为结构化冲突交给用户解决。
