# 意图流转：Intent 之间的关系

中文 | [English](../EN/intent-flow.md)

关系记录目标之间的联系：一个目标从哪里来，受什么制约。你用 `itt` 写下关系，IntHub 的「流转」页把它们画出来。

关系只存在于 Intent 之间。每个 Snap 本来就归属一个 Intent，不需要额外的关系。

## 五种关系

每条关系记在一个 Intent（B）上，指向另一个 Intent（A）。

| 类型 | B 上的写法 | 含义 | 流转页上的样子 |
|---|---|---|---|
| **组成** `part_of` | `--part-of A` | B 是 A 的一部分：B 完成或放弃后，A 才算完成 | 从 A 的主干分出的线，B 端是实心圆点；已结束的组成部分汇回 A 所在行 |
| **衍生** `derived_from` | `--derived-from A` | B 是做 A 时产生的新目标，但 A 的完成不依赖 B | 从 A 的主干分出的浅色线，B 端是空心圆点，不汇回 |
| **继承** `succeeds` | `--succeeds A` | B 接过 A 的目的继续推进：下一阶段、改换方案、合并重复目标 | 从 A 指向 B 的粗箭头，通常在同一行 |
| **依赖** `depends_on` | `--depends-on A` | B 要等 A 完成才能推进 | 从 A 指向 B 的细箭头：被阻塞时为琥珀色，已满足时为绿色，已失效时为红色 |
| **对立** `conflicts_with` | `--conflicts-with A` | A 与 B 不能都按现在的表述达成：互斥的方案，或相反的目标 | 标有 vs 的虚线：一方结束前为琥珀色，之后变淡 |

前三种说明 B 从哪里来：在 A 之内（组成）、因 A 而生但在 A 之外（衍生）、接替 A（继承）。后两种说明 B 受什么制约：必须等 A（依赖）、不能与 A 并存（对立）。不属于这两类的情况一律视为无关，不记录。

用它们就能画出分支、流转与汇合：

- **分支：** 组成、衍生，以及一个目标被多个后继继承。
- **流转：** 继承。
- **汇合：** 组成部分结束后汇回上级；多个目标被同一个后继继承，比如合并重复目标。

「继承」指接续目的，类似接班，和面向对象里的子类无关。更具体的子目标属于组成或衍生。

这里有意不提供「相关」「参见」这类弱关系：它们没有判断标准，Agent 会滥用，图很快就会变成噪音。

## 写下关系

```bash
itt intent create "接入 Apple Pay" --why "…" --part-of intent-003
itt intent relate intent-007 --depends-on intent-004          # 之后随时补记
itt intent unrelate intent-007 intent-004                      # 撤回这对 Intent 之间的有效关系
itt intent cancel intent-005 --into intent-008 --reason "重复"  # 结束它，由 intent-008 继承
itt show intent-007                                            # 查看两个方向的关系及其状态
```

`itt intent create` 可以带一个上级（`--part-of` 或 `--derived-from`），以及任意多个 `--succeeds`、`--depends-on` 和 `--conflicts-with`。`itt intent relate` 一次记录一条关系。

`done` 和 `cancel` 都接受 `--into`：结束这个 Intent，并记录目标 Intent 继承它。如果两者原本对立，这条对立关系会被撤回，因为为了一方而结束另一方，本身就解决了对立。

规则如下：

- 同一对 Intent 之间同时最多一条有效关系。
- 每个 Intent 最多有一个上级：组成或衍生只能有一条，并且只指向一个 Intent。
- 上级关系、继承、依赖都不能成环。
- Intent 不能关联自己，关联的目标必须存在。
- 已结束的 Intent 不能再新增组成部分。
- 关系只追加。撤回只是把记录标为已撤回，记录本身保留。

## 状态如何得出

关系的状态不单独存储。`itt` 和 IntHub 根据两端 Intent 的状态推算，所以两者始终一致。

| 类型 | 状态 |
|---|---|
| 组成 | 进行中 → 已完成 / 已放弃；如果 A 结束时 B 仍未结束，显示上级已结束 |
| 衍生 | 无，只表示来源 |
| 继承 | A 未结束时待交接 → A 结束后已交接 |
| 依赖 | A 未完成时被阻塞 → A 完成后已满足；A 被取消则已失效 |
| 对立 | 双方都未结束时未解决 → 任一方结束后已解决 |

需要处理的状态（上级已结束、待交接、被阻塞、已失效、未解决）会出现在 `itt inspect`、Agent 收到的开局上下文和 IntHub 的接续简报里。

`itt` 只报告这些状态，不做强制。你可以在组成部分未结束时结束 A，也可以继续推进被阻塞的 B。状态会告诉你和下一个 Agent 哪里需要处理。

## 流转页

每个 IntHub 项目都有「流转」标签。它显示 IntHub 上的 `main`，所以新关系要到达那里的 `main` 后才会出现。

- 有关系的 Intent 分组摆放：有未结束工作的组在前，先向右、再向下填满页面。每个 Intent 是一张卡片，角上显示创建日期。
- 组成和衍生的子目标排在上级右侧一列，共用一条主干。继承者接在同一行。依赖或对立于另一个 Intent、又没有上级和前任的 Intent，排在对方右侧。
- 已结束的组成部分汇到上级所在行的一个点上。只有一个已结束的组成部分、上级后面也没有继承者时，既不画汇合点，也不画汇回的线。
- 线型按上表区分。琥珀色表示这条关系需要处理。图例只列出当前用到的标记。
- 卡片颜色只表示状态，并始终配有文字。
- Decision 画成菱形，挂在来源 Intent 下方。项目级 Decision 放在顶部的「项目」一栏，已废弃的显示为空心。
- Snap 不单独画出。卡片上显示 Snap 数量，点击卡片打开详情侧板。
- 没有任何关系的 Intent 列在图的下方。
- 「隐藏已结束」去掉已结束的 Intent，「聚焦于…」只看一个 Intent 及其直接关系。

## Decision 的来源

Decision 对整个项目生效。创建时，它会关联当时所有活跃的 Intent；之后新建或恢复的 Intent 也会关联它。

要记录 Decision 出自哪个 Intent，创建时加上 `--from`：

```bash
itt decision create "支付只走 PaymentIntent" --why "…" --from intent-003
```

来源只写入一次，之后不变。它只说明出处，Decision 仍然对整个项目生效。不加 `--from` 就是项目级 Decision。

来源不会自动推断。在某个目标进行期间写下的项目级规则，不一定出自这个目标，记错比不记更误导。只有 Decision 确实出自某个 Intent 时才加 `--from`。

## 兼容性

关系是可选的，没有关系的 Intent 不多存任何内容。如果项目用了关系，所有需要拉取的人都要使用 `itt` 7.2 或更新版本：某个已存在的 Intent 新增关系后，更旧的版本会拒绝这次拉取。
